# Atlas Design

Select from the requested outcome and existing context; ask a brief question only when an unresolved distinction changes the deliverable. An explicit method choice takes precedence. Load the needed references, not the whole collection.

## Modes

| Mode | Need | Read and follow |
| --- | --- | --- |
| **Wireframe** | Test hierarchy, content, navigation or responsive structure before polish | [HTML Wireframe](references/wireframe/html-wireframe.md) |
| **Model** | Show a polished static mockup or a credible interactive HTML flow | [HTML Prototype](references/model/html-prototype.md); select its mockup or prototype branch |
| **Experiment** | Answer an uncertain UI or state-model question with throwaway code | [Prototype](references/experiment/SKILL.md), then its UI or logic reference |

Follow the selected reference's method. If it requires an independent skill, resolve that skill through the host's available skills. Explain any missing required capability before proceeding.

## Rulings and transitions

The user's direction and accepted project decisions govern selection. Preserve any supplied visual commitment at the fidelity the selected artifact can actually demonstrate.

Wireframe is intentionally unfinished. Model handles faithful visual presentation and modeled interaction. Experiment answers a question cheaply; it does not pass a production fidelity gate. Choose among them by the uncertainty being tested, not by the word “prototype” alone. Carry agreed structure, representative content, states, decisions and open questions forward when increasing fidelity. A rough experiment does not silently approve a final design.

Motion in an artifact demonstrates a design decision; give it a clear purpose and preserve accessible feedback. Production motion, visual craft and accessibility implementation belong to Atlas Implement. Hand off the chosen artifact, states, tokens and interaction intent without treating a mockup as production delivery.

Prototype's UI reference includes promotion into real code. Treat promotion as a distinct implementation engagement: hand the captured variant, decisions and recovery pointers to Atlas Implement when production work is authorized. A prototype request authorizes experimentation, not automatic production promotion. Follow the method’s capture and recovery requirements; surface unavailable tracker or branch access rather than claiming capture.

## Independent routes and completion

When consequential frontend choices need an interview and visible alternatives, offer **Atlas Decide → Shape**. Decide is manual: enter that engagement only when the user deliberately requests or selects it. Continue routine design judgments within the requested artifact work. Once Shape supplies a commitment, resume the appropriate design method with its selected references, fixed elements, allowed adaptations and unresolved choices.

Use Impeccable for work centered on its design, review or polishing expertise. The cinematic Animated Driven Frontend workflow remains a deliberate separate engagement; offer it when appropriate and preserve its manual contract.

Use the selected method's verification and handoff. Report the artifact, what it proves, the decisions and commitment it preserves, and any unverified states or unresolved choices. Code inspection alone does not prove rendered fidelity.
