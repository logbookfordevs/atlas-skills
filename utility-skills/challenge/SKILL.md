# Challenge

Try to disprove the current conclusion before the user acts on it. The subject can be an investigation, explanation, estimate, proposal, design or implementation. A conclusion that survives scrutiny is a valid result.

Read and follow [Interrogate](references/interrogate.md). It loads [Council](references/council.md) for the review brief and synthesis, and [Doubt discipline](references/doubt.md) for context preparation, reconciliation and stopping.

Use Team Up's bundled Arena for the specified phases, with Challenge's review brief and evidence rules. Team Up owns role, model, effort and dispatch selection; Challenge owns the question, findings and verdict. Reviewer count follows the scope and useful independent perspectives, rather than a fixed council size.

Keep the assessment advisory. Product code and external records remain read-only. Existing checks and owned scratch probes may run in isolated state; disclose prerequisites for probes that cannot safely run. Proposed repairs, PR changes and publication require the task's existing authorization. Explain what changed in the assessment, what survived, and what remains unknown; never equate reviewer agreement with proof.
