Tale of the tape

Run as a Team Up Arena. Each skill was the only variable: both sides ran on Claude Opus 5.5, saw the same seed file and context, and wrote to isolated folders. Contestants were told to follow their skill's own loading rules and cite the rules they applied.

  1. 1 · AuditSix shards read every instruction file of both skills, checking line ranges, and built rule inventories with line citations. The first two codex auditors truncated their reads, so their work was discarded and redone.
  2. 2 · SeedsTwo flawed pages based on Creative Room, plus a hidden list of 25 skill-neutral planted defects, written before any run.
  3. 3 · FightSix runs: landing refine, in-app refine and new direction, once per skill. Non-interactive: no run could ask the user.
  4. 4 · Captureagent-browser screenshots at 1440 and 390, a Tab-focus shot, axe-core WCAG 2.1 AA, overflow, infinite-animation count and a reduced-motion pass.
  5. 5 · Blind judgesG (GPT-6.1 Sol, high) and M (Gemini 3.8 Flash, high) scored anonymised X/Y outputs per pillar against a written rubric. The mapping was sealed.
  6. 6 · Rule judgeUnblinded GPT-6.1 Sol combined the verdicts, preferring G's line-cited evidence, and tied each win to rules it checked in both skills' files. Six citations were then spot-checked by hand.

Why these tasks

  • Refine, don't build. atlas-craft only refines existing interfaces. A from-scratch build would score its refusal, not its craft. A shared flawed seed is where both skills actually overlap.
  • Landing vs in-app. impeccable treats them as different modes (Persuade vs Operate), and craft doesn't. The real Desk screen also tests empty, loading, error and destructive states that a landing page never shows.
  • A third, deliberately unfair task: "new visual direction". It exposes refusal behaviour instead of assuming it.
  • Real material: Creative Room's README, the Desk's real PRODUCT.md and DESIGN.md, and gallery stills made by the studio's own tools. Creative Room's code was never touched.

Landing vs in-app

Landing (Persuade)

  • impeccable 4 wins, 0 losses, 4 draws. Both judges gave it Layout, States, Motion and UX.
  • Decisive rule: Persuade's opening must "expose a clear action… in its working form" (mode-persuade.md:9). impeccable shipped a copyable pnpm desk:start, while Craft's "Start the Desk" scrolled.
  • Craft kept a three-card scaffold, which impeccable's craft-floor bans as page structure (craft-floor.md:25). Craft has no equivalent rule.
  • Color, type, a11y and copy were all near-identical: both reached 0 axe violations and identical contrast.

In-app (Operate)

  • Even on pillars: Craft won Layout and Accessibility, impeccable won States and Motion, four draws.
  • Craft's mechanical depth showed here: preserved accessible names, a 3:1 input boundary, a native dialog, and more planted defects fixed (9 vs 7 per G).
  • impeccable still won both ship picks: its states connect (retry settles), its error copy is product-true, and its loading respects reduced motion.
  • Craft's single biggest loss is an execution bug, not a missing rule: its retry deadlock goes against its own ui/index.md:13.

Honest caveats

Sample and setup

  • n = 1 per cell. One run per skill per task. G's own notes show single bugs swinging whole pillars (the retry deadlock, the hidden mobile names).
  • I wrote the seeds and the defect list. I wrote them skill-neutral and before any run, but a different seed would test different rules.
  • Home advantage. The Desk's real PRODUCT.md and DESIGN.md were originally made with impeccable's schema. A schema comment was stripped from the judges' copy, but impeccable's context script reads exactly this format.
  • Non-interactive. Neither skill could ask the user. That penalises Craft's "needs its own decision" path most, and it also pushed impeccable off its decision-page contract (new-work.md:51).
  • Static stand-ins. These are single-file HTML pages, not the React Desk, so there's no real persistence. Both outputs claim saves they can't perform.

Judging

  • Judge M was lenient: it marked all 25 plants fixed for both skills. Where the judges split, the combined result favours G's line-cited evidence. With M alone, impeccable would win more pillars.
  • Model families: contestants were Claude, blind judges GPT and Gemini (to avoid self-preference), and the rule judge GPT. Some audit shards were Claude Sonnet after the codex reads truncated.
  • Blinding is partial. Judges didn't know the methods, but the two outputs differ in style. The direction round can't be blinded, because one side submitted nothing.
  • Equal weights for pillars and surfaces is a choice. The bonus round is reported separately, not averaged in.
  • No human judge, no screen reader, and no real-device test. Runtime checks were automated (axe, metrics, screenshots).
