## What do the six methods actually do, and should Atlas adopt them?

### Takeaway

Keep Pstack's understanding and design methods as separate original-name packages, with targeted portability patches and explicit dependency bundles. Their outputs differ enough to be useful together; a category named “understand” or “design” does not itself justify an `atlas-*` wrapper. The meaningful potential composition is routing the two incompatible `teach` contracts if Atlas elects to distribute both in one installation.

#### `how`: architectural comprehension

- Purpose: explain runtime flow, architecture, placement, ownership, and layering at senior-engineer onboarding depth. It explicitly directs motivation questions to `why`; its explanation is a read-only output, not implementation. Invocation is manual (`disable-model-invocation: true`). [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/how/SKILL.md#L1-L11)
- Required package contents: `SKILL.md`, `references/explorer-prompt.md`, and `references/explainer-prompt.md`. A simple question still spawns one explainer; complex questions spawn 2–4 explorers then one explainer. Parent presents the result with only light edits. The templates require exact components/files/flows, boundaries, gaps, contradiction reconciliation against source, and diagrams when helpful. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/how/SKILL.md#L13-L38); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/how/references/explorer-prompt.md#L7-L35); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/how/references/explainer-prompt.md#L17-L55)

Cursor defaults are Grok explorer and Claude explainer, including same-family fallback rules. No other Pstack skill is invoked and no `principle-*` is referenced. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/how/SKILL.md#L11-L30)

#### `why`: historical rationale with confidence tiers

- Purpose: reconstruct decisions, tradeoffs, incidents, thresholds, and motivation from history. It anchors exact files/symbols/commits/PRs first, then searches up to seven evidence categories: source control, issues, docs, chat, infrastructure, errors, analytics. It discovers available MCPs instead of hard-requiring seven named vendors. Invocation is manual. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/SKILL.md#L1-L49)
- Required package contents: all 12 Markdown files under `why/references/`: epistemics, investigator template, synthesizer template, source-playbook index, seven category examples, and incident-postmortem addendum. Its source examples are git/gh, Linear, Notion, Slack, Datadog, Sentry, and Databricks. The source index explicitly permits adapting another MCP in the same category. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/references/source-playbook.md#L1-L17); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/SKILL.md#L51-L56)
- The source-control investigator is mandatory; available sources default to full coverage, with documented null results. A skip requires no matching MCP or proven irrelevance, with a written justification. A trivial inline answer is exceptional and requires showing all seven available category searches would be redundant. With ordinary single-source-per-category interpretation, this means 1–7 investigators and one synthesizer, not a fixed seven-investigator minimum. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/SKILL.md#L58-L86)
- Despite the README saying to also install `how`, the runtime only describes `how` as a companion. It never tells `why` to run or read `how`. Therefore `how` is a useful companion, **not a hard runtime dependency of `why`** at this pin. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/README.md#L26-L37); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/SKILL.md#L7-L9)
- The epistemics contract is a substantive strength: Direct, Supported, Inferred, Speculative, Unknown; no intent inferred from code mechanics; preserve contradictions; spot-check citations; list unavailable sources. The synthesizer must not write files, commit, or modify external state. `why` nevertheless requests agent mode (`readonly: false`) because Cursor Ask mode strips MCP access; investigators are told not to write. Read-only *behavior* and a Cursor *mode flag* are distinct here. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/references/epistemics.md#L5-L71); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/references/synthesizer-prompt.md#L29-L45); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/SKILL.md#L11-L17)
- External assumptions: shell git and authenticated `gh` with a GitHub PR convention are treated as always available. Non-GitHub repositories, shallow history, private PRs, missing `gh`, unavailable historical retention, and inaccessible MCPs require honest gaps. The source playbooks explicitly treat authentication and retention limitations as gaps, and the Databricks playbook requires bounded read-only queries and schema discovery. Sentry optionally invokes Seer for hypotheses, which is an external analysis operation, not merely reading a cached issue. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/SKILL.md#L25-L27); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/references/sources/slack.md#L3-L17); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/references/sources/databricks.md#L14-L27); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/references/sources/sentry.md#L47-L53)

**Vote: package original `why`, with bounded capability/portability patch. Confidence: high.** Preserve its epistemics and coverage map. #### Pstack `teach`: a conversation that teaches the current code/change

- Purpose: combine `how` mechanics and `why` rationale into plain teaching, at the person's pace, for an existing change/subsystem. It explicitly says the goal is understanding rather than changing anything. `how` and `why` are real skill invocations, normally in parallel. Their outputs can be reworded, but `why` confidence language must survive. Invocation is manual. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/teach/SKILL.md#L1-L14)
- Hard closure: `teach` + `how` + `why` + **`unslop`** and all those folders' local reference files. The README's teach row omits `unslop`; the leaf explicitly says every response goes through that skill. It invokes no principle leaf. `why` itself does not expand that closure through `how`; `teach` invokes both directly. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/README.md#L28-L34); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/teach/SKILL.md#L11-L19); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/unslop/SKILL.md#L1-L9)
- It forbids quizzes and repeated “say it back” pacing. It starts with a small explanation and adds layers conversationally. For three or more moving parts it mandates incremental diagrams; for spatial explanations it directs actual image generation, which is an external capability/cost requirement if that situation occurs. This is stronger than merely recommending Mermaid. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/teach/SKILL.md#L13-L19)
- It advises keeping `why` narrow by default, with a scoped git-plus-one-or-two-source ask, while `why` itself only permits skipped categories for unavailability or proven irrelevance. This is a real internal scope ambiguity, not proof that the full sweep can always be skipped. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/teach/SKILL.md#L14); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/why/SKILL.md#L70-L77)

**Vote: package original Pstack `teach` with its complete closure and small scope/capability patches. Confidence: high.** Preserve teaching behavior. If image generation is unavailable, a truthful diagram fallback should be a patch, not a new Atlas brand. It does not need an Atlas Understand composition with `how` and `why`: it already is the upstream synthesis entry point, while the leaves remain useful directly.

It maintains `MISSION.md`, `RESOURCES.md`, learning records, numbered HTML lessons, reusable assets, reference HTML, and `NOTES.md`. #### `arena`: same-task alternatives with synthesis

- It frames a shared candidate brief and separate rubric, isolates writable outputs, launches N parallel candidates, cross-judges completed candidates, reads/scored all outputs, chooses a base, selectively grafts winners from the losers, and verifies the synthesized artifact. It returns a synthesis note including rejected alternatives, dropouts, and verification. This is useful beyond code, and distinct from an ordinary delegated task. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/arena/SKILL.md#L7-L48)
- Hard/principle references: separate-before-serializing-shared-state, laziness-protocol (named without a link), redesign-from-first-principles, prove-it-works. It references no other workflow skill directly, but `prove-it-works` has a conditional `show-me-your-work` call, and that adds `unslop` plus transcript audit and cross-model review requirements. Thus “arena works alone” in README is true only if principle references are treated as fully restated advice; it is false as a complete linked skill closure. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/README.md#L20-L24); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/arena/SKILL.md#L17-L44); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/principle-prove-it-works/SKILL.md#L18-L22); [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/show-me-your-work/SKILL.md#L34-L74)

#### `swarm`: distributed coverage/races with one evidence report

- It partitions work, races identical briefs, or mixes both, declares first-pass/rank-all/best-of before spawning, gives isolated write outputs, requires exact SHAs and measurement methods in relevant briefs, and returns one table/report with PASS/ISSUES/BLOCKED and explicit gaps. Missing required evidence triggers one respawn, then a gap; a gap is not a pass. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/swarm/SKILL.md#L7-L48)
- It calls no other Pstack skill and references no principle leaf. It does require N workers, or sequential execution if the host has no subagents. It documents Cursor cloud execution plus local alternatives for Claude Code/OpenCode/Codex/Pi, and `cloud_base_branch` only when starting cloud workers from a non-default pushed branch. This is an assumption about available pushed state, not an instruction to push or merge a branch. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/swarm/SKILL.md#L24-L38)
- Resource behavior: N is total workers, not concurrency limit. The leaf gives no maximum N, total cost, or rolling scheduling policy, so a host with bounded parallelism needs a deliberate queuing adaptation. No automatic merge, release, deploy, or external message is part of this leaf. [Source](https://github.com/backnotprop/pstack/blob/1f0f9c3bac03c4297f6fc8f7644fa412eda57085/skills/swarm/SKILL.md#L20-L48)

**Vote: package original `swarm` with Team Up/host-concurrency patch. Confidence: high.** It adds coverage accounting and race rules that Team Up lacks; retain it as a workflow complement, with Team Up selecting valid roles/models.

### Inferences

- A complete original package set is better than a new Understanding composition: `how` answers mechanics, `why` answers historical rationale, and Pstack `teach` already combines them. Add the actual transitive packages rather than generating a fourth router with nearly identical semantics. Evidence: the explicit contracts above, especially teach's real invocations.
- Most host differences need a patch under the original name: delegation API syntax, model selection through Team Up, concurrency handling, missing image generation, and git/gh availability. New Atlas names should signal a substantively different combined contract, not just local tooling.
- Genuine combined-method conflicts need precise rulings: selected TDD requires confirmed seams/red-before-green; explicit human design gates override architect's default no-checkpoint path; Team Up replaces incompatible Pstack role/model defaults when both are active. Merely having Atlas Implement, Grill, or Wayfinder installed does not create an execution conflict.
- `teach` is the only direct name collision among these candidates. Selecting Pstack teach for engineering use and Matt teach for a separate learning-workspace profile preserves both upstream contracts without adding a router. If both must coexist, a mode router is warranted because the difference determines whether the agent quizzes the user and writes a durable course.

## What is the complete dependency model, and what does each principle contribute?

### Takeaway

Package the needed dependency closure, keep the index cheap, and load the applicable leaf only when applying it. README dependency claims omit real edges and should not drive an Atlas installer.

### Inferences

- Do not flatten the 24 principles into global rules or a mandatory monolithic skill. Preserve leaf names/provenance and package dependency closures; offer a short catalog/index. The original mode's instruction to read each applied leaf is already sufficient lazy loading if used correctly.
- Prioritize practical additions outside mandatory closures: explain-the-number + benchmark-checklist, model-the-domain, type-system-discipline + TypeScript practices, idempotence, and structural lesson encoding. Existing Atlas Domain Modeling, codebase-design, Implement/TDD, and pe-verify remain the workflows that own their richer contracts.
- Principle policies are not all simultaneously satisfiable literally. Sequence says every unit is green and delivery can begin with a failing test; outcome permits planned intermediate breakage. A complete distribution needs explicit phase/verification boundary semantics when it combines them, rather than appending both as universal imperatives.
- The full native closure can be distributed without AFK. AFK may help installation/selection, but none of these runtime methods requires an AFK server or CLI. Model selection, transcript paths, git/gh, MCP tools, image generation, and host concurrency are the real capabilities that must be declared or adapted.

### Gaps

- The dependency table is conservative about cross-referenced principles: some content is partially restated inline, but the source calls these named skill principles. A maintainer must decide whether to ship native leaves or intentionally vendor relevant references. Claiming standalone completeness while omitting named referenced rules is the weakest option.
- This appendix audits every leaf and direct assigned-method references. It also identifies major other runtime incoming references and the mode's universal index; it is not an exhaustive exact-string occurrence inventory of every README/guide example.

### Inferences

Strongest recommendations, ordered:

1. **Adopt original `how`, `why`, `arena`, `swarm`, `architect`, and Pstack `teach` as independent complementary packages**, subject to the bounded patches above. Do not rename them merely because of patches. Include required reference files and dependency leaves in Atlas itself so it remains usable without AFK.
2. **Make the dependency graph a packaging input verified from source**, not copied from README: teach adds unslop; why does not hard-invoke how; architect has conditional why/interrogate and a 14-principle conservative closure; arena has principle/trail closure; swarm is genuinely independent of other Pstack packages.
3. **Use Team Up for valid role/model/effort selection** and adapt host dispatch/concurrency. Preserve how's explore/explain split, why's source ownership/epistemics, arena's scoring/synthesis, swarm's gap accounting, and architect's usage-first type design.
4. **Keep explicit invocation semantics visible.** These six Pstack methods are manual. Architect means design **and implementation** unless checkpoint requested. Merely installing it must not trigger design bakeoffs before every ordinary implementation. Existing Atlas Implement remains a selectable TDD/Source discipline; only selected-method conflicts need rulings.
5. **Do not compose how+why+teach into an Atlas umbrella by default.** Teach already supplies upstream synthesis, and the two analytical leaves have distinct direct use. For the two `teach` providers, prefer mutually exclusive package/profile selection with descriptive catalog labels; add an Atlas Teach mode router only if simultaneous access is a concrete requirement.
6. **Keep principles contextual and prioritize real gaps.** Ship mandatory closures and a short index. Prioritize measurement integrity, domain/state modeling, idempotence, structural enforcement, and concurrency isolation. Do not inject all 24 into every session. Keep risky migration/autonomy/temporary-breakage principles narrowly scoped.
7. **Record provenance as backnotprop's modified mirror of Lauren Tan/Cursor Pstack, at the exact pin, with MIT notice.** Do not claim Cursor equivalence. If future adoption pulls external sources with no verified redistribution license, that missing permission is a packaging blocker for those sources, not a rejection of their behavioral quality.

### Gaps

- **Upstream equivalence remains unverified.** The shallow local clone exposed only `main`/origin main, not a fetched exact upstream branch. Attempts to open Cursor `837067b` and its raw how file returned web cache misses; API commit retrieval was inaccessible; a read-only sparse clone attempt failed DNS in this environment. Therefore the mirror's short upstream SHA could not be resolved to a full immutable Cursor pin or compared byte-for-byte. A report must not upgrade the sync commit message to proof of equality.
- **Decide simultaneous teach exposure before implementation.** Is optional profile selection enough, or does Atlas need one installed router exposing course mode and code-explanation mode? The latter is a meaningful composition, but not yet an evidenced user requirement.
- **Set the narrow-scope and external-capability fallbacks.** Explicit scope for why, missing git/gh/history, lack of image generation, missing transcript access, unavailable cross-family review, and finite host concurrency need concrete wording and focused host experiments before declaring the distribution fully portable.
- **Declare verification-unit semantics if adopting conflicting principles together.** Planned temporary architecture breakage, failing-test-first delivery, and “every unit green” cannot be stacked as unconditional rules. The unit/phase definition and explicit user checkpoints resolve the conflict.
