# Atlas Design behavioral evaluation

Task cases for live model evaluation; execution remains pending. Observe actual reference loading, deliverables, rendered behavior and source fidelity, not authored prose.

| Request / context | Expected behavior |
| --- | --- |
| Consequential frontend choices need an interview | Offer manual Decide → Shape; routine artifact work does not force an interview. |
| Test navigation and hierarchy without polish | Wireframe: unfinished responsive HTML structure. |
| Polished static pricing-page mockup | Model: static presentation, representative content, no fake interactions. |
| Interactive signup with loading/error/recovery | Model: bounded flow with keyboard/mobile states and a truthful real-system boundary. |
| Does this state machine handle cancel after submit? | Experiment: throwaway logic reference and observable awkward states. |
| Compare radically different UI structures | Experiment: isolated UI alternatives, preserving existing data. |
| Animate a dropdown in the production app | Implement → Motion; do not treat a production change as a design artifact. |
| Prototype an animated interaction to test direction | Keep demonstration in the artifact; motivate motion and preserve reduced-motion behavior. |
| Wireframe then modeled flow | Carry agreed structure/content and visual commitment forward; name fidelity limits. |
| Prototype requested, no production change authorized | Keep experiment; promotion requires implementation scope and capture access. |
| Shape commitment supplied | Preserve fixed elements, states and allowed adaptations without reopening settled direction. |
| Cinematic frontend production | Offer independent Animated Driven Frontend, preserving its deliberate engagement. |

Record rendered evidence and user outcome separately from lint, package integrity or metadata checks. Astra behavior and quality remain unmeasured. Full PE Design’s mode structure is not adopted by this boundary change.
