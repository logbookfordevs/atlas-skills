# Atlas Design

Choose from the requested outcome and context, honoring an explicit choice. Ask only when ambiguity changes the method. Read and follow the relevant references; combine methods when they serve complementary parts of the task.

| Mode | Need | Read and follow |
| --- | --- | --- |
| Wireframe | Test hierarchy, content and responsive structure | [Wireframe](references/wireframe/html-wireframe.md) |
| Model | Show a polished mockup or modeled interaction | [Model](references/model/html-prototype.md) |
| Experiment | Answer a UI or state-model question with throwaway code | [Experiment](references/experiment/SKILL.md) |
| Style | Establish or refine an HTML artifact’s visual treatment | [Style](references/style/design-artifact.md) |

Resolve selected sources’ design-artifact calls to Style. Load Style when the artifact needs visual treatment. Preserve accepted direction, content and states across increasing fidelity. Prototype promotion requires a separate authorized implementation engagement. For a selected visual reference, read [visual commitment](references/commitment/visual-commitment.md). Production craft and motion can use Atlas Craft and Atlas Motion.

Resolve skills required by the selected reference through the host. If a required capability is unavailable, explain the gap before proceeding with that method.
